## 2026-09-09 实际故障结果（暂停发布）

沙盒记录 `build/sandbox-rollback-0.1.0.11/Output/rollback-run-20260909-194513/`：`after-stage`、`after-package` 均 PASS（返回 7，故障点及回滚日志齐全，前后快照 0 差异）；`before-commit` FAIL（返回 0，194 项快照差异，未触发回滚）；`after-state` 未运行，工具按设计停止。

根因是 Inno 6.2.2 会处理 `ssPostInstall` 中的异常并继续进入 `ssDone`。旧代码在 `ssDone` 无条件置 `Completed=True`，导致提交失败仍跳过回滚并返回成功。失败现场为 `.11` Package/卸载项与 `.8` 产品记录并存；旧 `.8` 文件、项目证书及旧菜单未改变，`.upgrade-2084b70b78b24dcba026492a9ed60008/backup.json` 保留。配置当时不存在，不声称通过了非空配置保留测试。

0.1.0.13 修复的是安装事件状态和错误码，不改变已测试的部署助手算法。旧失败记录不得改成 PASS。若导出旧现场后改用新沙盒准备基线，这只是测试环境重建，不代表原 `.11` 自动回滚成功。当时要求新包重新完成四个真实故障测试；`.13` 后续失败，`.14` 后续验证结果见本文顶部。

本机曾完成健康 0.1.0.8 → 0.1.0.11 升级；用户另反馈本机卸载重装及第二台 Windows 11 使用正常。证据范围见 [验收记录](TESTED-BASELINE.md)。该版本后来在隔离环境的故障回滚测试中失败；`.14` 后续结果见本文顶部。

以下为当时的 `.11` 测试步骤，保留作历史记录，不是当前执行指令。后续 `.14` 测试已完成，不应据此重建基线或运行旧故障包。

## 历史步骤：正常升级

1. 保留已工作的 0.1.0.8，记录安装目录、用户配置内容、Package、卸载项和项目证书指纹。
2. 关闭正在执行解压的窗口及 SmartZip 设置窗口。正常启动 `SmartZipSetup-0.1.0.11-test.exe`。
3. 应自动使用原目录，不允许升级中迁移；验证旧身份通过后跳过重复证书授权。
4. 安装完成后确认当前用户的 Package 为 0.1.0.11，外部位置为新版本目录，VerifyIsOK=True 且无 Modified/NeedsRemediation 等异常；现代菜单可用，用户配置不变，证书创建者属性继续保留。
5. 测试 ZIP/RAR/7Z、中文/空格/特殊字符、多选。确认旧原版 SmartZip、旧 UnZip 和独立 7-Zip 未受影响。
6. 同版重复安装和旧版本安装包应拒绝，不应写入数据。
7. 通过正式卸载入口卸载：移除 Package、项目状态、所有由本产品记录的版本目录与快捷方式；证书按最初所有权处理，用户配置保留。

## 历史步骤：实际回滚测试（仅测试环境）

先准备独立 Windows 11 虚拟机或 Windows 沙盒，并在来宾系统核实 AppX 部署、证书助手和本项目基线安装可用。不能只换安装目录或新建本机用户替代隔离环境：测试证书信任涉及 LocalMachine。

2026-09-09：用户已批准并完成沙盒依赖启用及主机重启。当前沙盒已正常安装 0.1.0.8；来宾实际为 Enterprise 26100.9278，不应将其写成主机的 Pro 25H2 26200.9278，也不能替代完整的另一台 25H2 验收。不得在正常使用的主机 0.1.0.11 安装上执行下列故障包。沙盒仅获得只读测试材料和专用可写日志目录，私钥、仓库凭据和主机安装目录不共享；关闭沙盒前保存结果，不能把沙盒销毁当作安装器回滚成功。

从已工作的 0.1.0.8 基线开始，每次只运行一个故障构建：

```powershell
pwsh -File .\build.ps1 -Signing Test -Version 0.1.0.11 -FaultAt after-stage
pwsh -File .\build.ps1 -Signing Test -Version 0.1.0.11 -FaultAt after-package
pwsh -File .\build.ps1 -Signing Test -Version 0.1.0.11 -FaultAt before-commit
pwsh -File .\build.ps1 -Signing Test -Version 0.1.0.11 -FaultAt after-state
```

生成的文件名包含 `-fault-`，不要发布给普通用户。故障点分别覆盖文件写入、Package 切换、Inno 元数据提交后以及产品状态部分更新后。

每次失败后重新获取旧 Package，验证健康状态、COM 和菜单可用，旧卸载 EXE/DAT/MSG、快捷方式、产品状态与备份内容一致，新目录被清理，原证书和用户配置未变化。版本号恢复但健康检查失败，仍算回滚失败。
若旧 Package 恢复被 Windows 拒绝，应明确报回滚不完整，保留文件和 `.upgrade-随机编号` 备份，不继续删除依赖；不得人工清理后宣称自动回滚成功。

备份不含自定义注册表 ACL，保存的是原始值及类型、卸载文件/快捷方式字节。断电/杀进程恢复不承诺自动重试；发现不完整状态会阻止继续覆盖。升级期间不要启动另一个旧版卸载器或手工修改项目文件。

## 历史步骤：修复版新沙盒的顺序测试入口

主机运行 `pwsh -NoProfile -File tests/Prepare-SandboxRollback.ps1` 只构建测试工具、执行纯函数自检和“拒绝主机执行”检查，并将四个已固定 SHA-256 的 `.14` 故障包及原 `.8` 基线材料放入独立的 `build/sandbox-rollback-0.1.0.14/`；不会覆盖旧 `.11` / `.13` 映射和日志、重新构建故障包、启动沙盒或运行安装器。旧证据必须保留，新沙盒重新检查及安装基线，不能沿用旧会话的状态文件；旧 `.11` 专用导出脚本不适用于 `.13` 现场。

用户在**新沙盒、基线安装确认成功后**运行 `C:\SmartZipTestInput\Run-Rollback.cmd`：

- 工具必须匹配 WDAG 账户、虚拟机、映射路径，以及本次基线的机器名/SID；先核验所有故障包 SHA-256，再检查原 0.1.0.8 的文件、Package 健康、路径、收据、COM/菜单声明及测试证书。
- 每个故障包仅运行一次，无界面升级且不重启、不强制关闭程序；超过三分钟停止后续测试，不杀进程。任一失败或已有测试记录都阻止继续执行。
- 每步前后保存安装目录和配置的逐文件 SHA-256、开始菜单、产品/卸载注册表原始值及类型、Package 健康和 manifest、项目 COM 登记、精确指纹的逻辑及物理证书位置、证书所有权键。CU 逻辑存储可能继承 LM 证书，不据此判断重复导入。
- 只有故障确实到达指定注入点、安装器返回失败、日志包含完整回滚且无不完整回滚，并且独立前后快照一致，才记 PASS。只有版本号相同不算通过。出现差异保留证据，不补注册、不删除残留。
- 输出在新映射目录 `Output/rollback-run-时间/`；每步包含 `before.json`、`after.json`、`differences.json`、`result.json`、Inno 和 helper 日志。四步通过也保持 0.1.0.8，不自动升级到任何正常候选安装包。
- 工具只验证登记及回滚，不激活 COM、不执行解压，避免持有旧包。现代菜单实际显示/调用、Explorer 稳定性以及完整安装/卸载字体仍须另行人工验收。若配置尚未创建，只能证明“未创建/未改变”，不声称测试了非空用户配置。

入口准备完成不等于真实回滚通过；结果必须来自上述沙盒运行日志。
